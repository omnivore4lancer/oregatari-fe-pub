================================================================
oregatari 画面別機能説明
================================================================

【凡例】
  ★ Mastra処理  … Google Gemini を使った AI 生成処理の内容
  ☆ フロー      … 処理の流れ（FE → BE → Mastra → Gemini → DB）


----------------------------------------------------------------
Screen 00: ログイン画面（00_login.png）
----------------------------------------------------------------
概要:
  メールアドレスとパスワードで認証する画面。
  未認証のユーザーはすべてのページからこの画面にリダイレクトされる。
  Supabase Auth を利用した認証基盤。

機能:
  - メールアドレス / パスワードによるログイン
  - ログイン状態はセッションで維持
  - 認証済みの場合はダッシュボードへ自動リダイレクト
  - ログイン失敗時はエラーメッセージをインライン表示


----------------------------------------------------------------
Screen 01: ダッシュボード（01_dashboard.png）
----------------------------------------------------------------
概要:
  ログイン後のホーム画面。作成した漫画作品の一覧を表示する。
  ここから新規作品の登録や、各作品の編集へ遷移できる。

機能:
  - 所有する作品をカード形式で一覧表示
  - 作品カードには表紙画像・タイトル・ジャンル・更新日時を表示
  - 「新しい作品を登録」ボタンから作品作成フローへ遷移
  - 作品カードのメニューから作品の削除が可能（確認ダイアログ付き）


----------------------------------------------------------------
Screen 02: 作品作成 — ステップ1: 基本情報（02_story_create_step1.png）
----------------------------------------------------------------
概要:
  4ステップの作品作成ウィザードの第1ステップ。
  物語のタイトルとストーリータイプ（ジャンル）を設定する。
  ここで設定した情報が以降の AI 生成の指針となる。

機能:
  - 物語タイトルの入力（必須）
  - ストーリータイプ（ジャンル）の選択（最大3つまで）
  - トグルチップ UI でジャンルを直感的に選択・解除
  - 選択中のジャンル数をカウント表示
  - 進捗をステップインジケーターで視覚化


----------------------------------------------------------------
Screen 03: 作品作成 — ステップ2: 世界観（03_story_create_step2.png）
----------------------------------------------------------------
概要:
  作品作成ウィザードの第2ステップ。
  物語の舞台となる世界観と時代を設定する。
  ここで入力した内容をもとに AI がキャラクターやストーリーを生成する。

機能:
  - 世界観設定のテキスト入力（必須）
  - 時代設定の選択: 現代 / 古代・中世 / 未来・SF
  - 追加要素の自由記述（任意・最大 300 文字）
  - 文字数カウンターをリアルタイム表示


----------------------------------------------------------------
Screen 04: 基本設定 — ストーリー（04_story_story.png）
----------------------------------------------------------------
概要:
  作品の時代背景と歴史ストーリーを管理する画面。
  AI によるストーリー自動生成と手動編集の両方に対応している。

機能:
  - 時代背景（左カラム）のテキスト閲覧・編集
  - 歴史ストーリーを「導入 / 展開 / クライマックス / 結末」の4章で管理
  - 縦タブで章を切り替えて内容を確認
  - 「AI 生成」ボタンでストーリー全章を自動生成（ストリーミング表示）
  - 生成中はモーダルでリアルタイムにテキストを表示
  - インライン編集（編集ボタン → 完了 / キャンセル）

★ Mastra処理（「AI 生成」ボタン押下時）:
  ワークフロー: story-generation-workflow
  使用エージェント:
    [1] Character Setup Agent（gemini-2.5-pro）
        - 既存キャラクターを読み込み、物語論の4アーキタイプ
          （メンター / シャドウ / ヘラルド / シェイプシフター）を自動判定
        - 不足しているアーキタイプのキャラクターを追加生成
        - 全登場人物ペアの関係性（方向・説明文）を自動定義
    [2] Story Writer Agent（gemini-2.5-pro）
        - タイトル・ジャンル・世界観・時代設定・登場キャラクターをもとに
          時代背景・導入・展開・クライマックス・結末の5パートを執筆

☆ フロー:
  FE 「AI 生成」→ POST /stories/:id/generate
    → character-setup-step（キャラ設定・関係性 DB 保存）
    → story-writer-step（本文執筆）
    → save-story-step（eraBg / intro / dev / climax / conclusion を DB 保存）
    → FE へ SSE ストリーミング出力（生成テキストをリアルタイム表示）

Screen 05: 基本設定 — 相関図（05_story_cast.png）
----------------------------------------------------------------
概要:
  キャラクター間の相関関係をビジュアルで管理する画面。
  登場人物リストとグラフを並べて表示し、関係性を直感的に把握・編集できる。
  相関図の初期データは、ストーリー生成時に Character Setup Agent が自動生成している。

機能:
  - 登場人物リスト（左カラム）: 名前・役割・配役アーキタイプを表示
  - 相関図（右エリア）: ノードとエッジのグラフで人物関係を視覚化
  - グラフ上でキャラクターを選択してハイライト（リストと連動）
  - キャラクターのクリックで詳細モーダルを表示
  - アーキタイプロールのクリックで役割説明モーダルを表示
  - キャラクター名・役割のインライン一括編集
  - 「追加する」から新しい登場人物を直接追加

★ Mastra処理（ストーリー生成時に自動実行済み）:
  エージェント: Character Setup Agent
  - 全キャラクターのアーキタイプロール（配役）を自動判定・保存
  - 全登場人物ペアの関係性（方向・説明文）を自動生成・DB 保存
  - この画面で表示される相関図のノード・エッジはこの処理の結果

Screen 06: キャラクター一覧（06_character_list.png）
----------------------------------------------------------------
概要:
  主人公・サブキャラクターの一覧と詳細を管理するマスター画面。
  左のリストでキャラクターを選択すると、右パネルに詳細が表示される。

機能:
  - 主人公とサブキャラクターを分けてカード形式で一覧表示
  - キャラクター選択でリストと詳細パネルが連動
  - 詳細パネルに「三面図」「基本情報」の2タブ
  - 三面図タブ: AI で生成したキャラクターデザイン画像（前面・側面・後面）を表示
  - 基本情報タブ: 名前・役割・配役・年齢・性別・スキル等をインライン編集
  - キャラクターの削除（確認ダイアログ付き）
  - 「新しいキャラクター」ボタンで作成フォームへ遷移

★ Mastra処理（「三面図を生成」ボタン押下時）:
  ワークフロー: character-three-view-workflow
  使用エージェント: Character Three-View Agent（gemini-2.5-pro / 画像生成モード）
  - キャラクターの名前・外見・性格・役割情報をもとに YAML プロンプトを構築
  - 「前面・側面・後面の三面図 ＋ 喜怒哀楽4種の表情」を1枚の設定画像として生成
  - 細田守風アニメ調の画風で統一

☆ フロー:
  FE 「三面図を生成」→ POST /characters/:charId/generate-three-view
    → build-prompt-step（character 情報 → YAML プロンプト生成）
    → three-view-agent-step（Gemini 画像生成）
    → Supabase 'character-images' bucket にアップロード
    → DB の character.imageUrl を更新
    → FE にストリーミング出力（完了通知）

Screen 11: エピソード作成（11_episode_create.png）
----------------------------------------------------------------
概要:
  AI を活用して新しいエピソードを生成する画面。
  右パネルに AI 編集者が常駐しており、相談しながら作成できる。

機能:
  - エピソード種別の選択: 「単独エピソード」または「続編」
  - 続編選択時は親エピソードを一覧から指定
  - 登場人物の選択（チェックボックス）
  - タイトル・要約・本文のヒント入力（任意）
  - 「ストリームで生成」: AI がエピソード本文をリアルタイムにストリーミング出力
  - 「バックグラウンドで生成」: 裏で生成し一覧に自動反映
  - 右パネルに AI 編集者アシスタントを常設

★ Mastra処理（「ストリームで生成」または「バックグラウンドで生成」押下時）:
  ワークフロー: episode-generation-workflow
  使用エージェント: Episode Writer Agent（gemini-2.5-pro）

  入力情報:
    - エピソード種別（単独 / 続編）
    - 続編の場合は親エピソードの内容（getEpisodeTool で取得）
    - 選択した登場人物と各キャラクターの重要度
    - タイトル・要約・本文のヒント（任意）
    - ストーリー全体の世界観・設定（getStoryTool で取得）

  処理内容:
    - 上記情報をもとにシナリオ脚本形式（3〜5シーン）のエピソード本文を執筆
    - 各シーンは「○{シーン名}」で区切られ、コマ割り生成の入力となる
    - saveMode=true の場合は saveEpisodeTool を呼び出して DB に自動保存

☆ フロー（ストリーム生成）:
  FE 「ストリームで生成」→ POST /episodes/generate/stream
    → build-episode-prompt（入力情報をプロンプト化）
    → episode-writer-step（Episode Writer Agent がシナリオ執筆）
    → saveEpisodeTool（タイトル・本文・登場人物を DB 保存）
    → FE へ SSE ストリーミング出力（生成テキストをリアルタイム表示）

☆ フロー（バックグラウンド生成）:
  FE 「バックグラウンドで生成」→ POST /episodes/generate/background
    → 非同期ジョブとして実行（FE はポーリングで完了を検知）
    → 完了後にエピソード一覧に自動反映

Screen 13: シーン管理 / マンガ作成（13_scene_management.png）
----------------------------------------------------------------
概要:
  エピソードのコマ割りと画像生成を管理するメインの漫画制作画面。
  ページのレイアウト・プロンプト・生成画像をここで一元管理する。

機能:
  - 左カラム: エピソード一覧でエピソードを切り替え
  - ページサムネイルリスト: 縦スクロールで全ページを俯瞰
  - 中央エリア: 選択ページを拡大プレビュー（ズーム調整可能）
  - 右パネル: コマ設定（プロンプト・セリフ等）と詳細情報の表示・編集
  - 「コマ割り再生成」: ページ全体のレイアウトをAIで再構成
  - 「ページ画像再生成」: 選択ページの画像のみ再生成
  - ページ生成状況をステータスバッジ（生成中 / completed）で表示
  - 生成中は透明オーバーレイ＋スピナーでリアルタイムフィードバック
  - ページがない場合は「新規生成」ボタンを表示

★ Mastra処理①（「コマ割り再生成」/ 「新規生成」ボタン押下時）:
  ワークフロー: panel-layout-full-workflow
  使用エージェント: Panel Layout Agent（gemini-2.5-pro）

  処理内容:
    [1] 既存ページデータをすべて削除（clear-existing-pages-step）
    [2] Panel Layout Agent がエピソードのシナリオ本文を読み込み、
        ページ・コマ単位に分割する
        - 「○{シーン名}」区切りでシーンを識別
        - 1コマ = 1アクション または 1〜2行のセリフ
        - 各コマにカメラアングル・構図・深度・背景・エフェクト等の
          演出情報を付与
        - キャラクターごとの表情・ポーズ・向きを指定
        - セリフ行（「キャラ名　「セリフ」」形式）を自動抽出し、
          コマのキャラクター情報にマージ
    [3] コマ割りデータを DB（EpisodePage / Row / Panel）に保存
    [4] 保存したコマ割りから各ページの YAML 画像プロンプトを自動生成・保存
        （verify-pages-step → generate-page-prompts-step）

☆ フロー（コマ割り再生成）:
  FE 「コマ割り再生成」→ POST /episode-pages/generate-layout-job
    → 非同期ジョブ（Job レコード作成・status=RUNNING）
    → panel-layout-full-workflow 実行
       ├ clear-existing-pages-step（旧データ削除）
       ├ panel-layout-step（Panel Layout Agent: コマ割り生成・DB 保存）
       ├ verify-pages-created-step（ページ数チェック）
       └ generate-page-prompts-step（YAML プロンプト自動生成・DB 保存）
    → Job 完了 → FE のポーリングで検知 → サムネイル更新

★ Mastra処理②（「ページ画像再生成」ボタン押下時）:
  ワークフロー: page-image-workflow
  使用エージェント: Page Image Agent（gemini-2.5-pro / 画像生成モード）

  処理内容:
    [1] 指定ページの YAML プロンプトを取得
        （未生成の場合は ensure-page-prompt-step で事前生成）
    [2] 登場キャラクターの三面図画像を参考画像として取得・base64 変換
    [3] YAML プロンプト ＋ キャラ参考画像を Gemini に渡して漫画ページ画像を生成
    [4] 生成画像が横向き（landscape）の場合は縦向き強制プロンプトで再生成
    [5] Supabase 'episode-pages' bucket にアップロード
    [6] DB の episodePage.imageUrl を更新

☆ フロー（ページ画像生成）:
  FE 「ページ画像再生成」→ POST /episode-pages/generate-image-job
    → 非同期ジョブ（Job レコード作成・status=RUNNING）
    → page-image-workflow 実行
       ├ ensure-page-prompt-step（YAML プロンプトの存在確認・未生成なら生成）
       └ page-image-step（Page Image Agent: 画像生成 → Supabase → DB 更新）
    → Job 完了 → FE のポーリングで検知 → サムネイル・プレビュー更新

  - ステップ形式の設定: 登場人物選択 / ビジュアルスタイル / レイアウト / あらすじ
  - 各ステップの完了数をプログレス表示
  - AI による表紙画像の生成（選択したキャラクターをもとに生成）
  - 表紙画像のリアルタイムプレビュー（右カラム）
  - 設定の保存（表紙を再生成せずに設定のみ保存）
  - 「公開する」ボタンでストーリーを Web 公開（確認ダイアログ付き）
  - 「公開取り下げ」で非公開に戻す（確認ダイアログ付き）

★ Mastra処理（「表紙画像を生成」ボタン押下時）:
  ワークフロー: cover-image-workflow
  使用エージェント: Cover Image Agent（gemini-2.5-pro / 画像生成モード）

  入力情報:
    - 選択したキャラクターの情報と三面図参考画像
    - ビジュアルスタイル設定（選択した画風）
    - レイアウト設定
    - あらすじ（description）
    - ストーリーの世界観・ジャンル情報

  処理内容:
    [1] build-cover-prompt-step
        - ストーリー情報・キャラクター情報・設定をもとに
          2:3 縦長表紙用の YAML プロンプトを構築
        - 選択したキャラクターの三面図画像を参考画像として取得
    [2] cover-image-agent-step（Cover Image Agent）
        - YAML プロンプト ＋ キャラ参考画像を Gemini に渡して表紙画像を生成
        - Supabase 'story-covers' bucket にアップロード
        - DB の publishSettings.coverImageUrl を更新

☆ フロー:
  FE 「表紙画像を生成」→ POST /publish-settings/:storyId/generate-cover-image-job
    → 非同期ジョブ（Job レコード作成・status=RUNNING）
    → cover-image-workflow 実行
       ├ build-cover-prompt-step（YAML プロンプト＋キャラ参考画像の準備）
       └ cover-image-agent-step（Gemini 画像生成 → Supabase → DB 更新）
    → Job 完了 → FE のポーリングで検知 → 右カラムの表紙プレビューに反映

Screen 20: ジョブ一覧（20_jobs.png）
----------------------------------------------------------------
概要:
  Mastra ワークフローによる AI 生成ジョブの実行履歴を管理する管理画面。
  生成の進捗確認・失敗時のエラー確認・使用モデルの把握に利用する。

機能:
  - ジョブをテーブル形式で一覧表示
    表示項目: 日時・物語/エピソード・ページ・種別・状態・使用モデル・エラー内容
  - ステータスフィルター: 実行中 / 完了 / 失敗
  - 種別フィルター: 画像生成 / コマ割り / 表紙画像
  - ページネーション（50件/ページ）
  - エピソード名のリンクからシーン管理画面に直接遷移
  - 使用モデル名・画像モデル名の表示（デバッグ・確認用）

★ Mastra処理（ジョブの種別と対応ワークフロー）:
  種別「コマ割り」    → panel-layout-full-workflow
    Panel Layout Agent がコマ割り生成 ＋ YAML プロンプト自動生成

  種別「画像生成」    → page-image-workflow
    Page Image Agent が YAML プロンプト → 漫画ページ画像生成

  種別「表紙画像」    → cover-image-workflow
    Cover Image Agent が表紙画像生成

  ※ すべて Mastra 上の非同期ジョブとして実行される
    BE は runId で状態を定期確認し、DONE / FAILED になると DB を更新
    FE はこの画面で最終結果（モデル名・エラー内容）を確認できる
